# Протокол измерений

## Источник данных
Консольный Intel PresentMon (ETW). FramePilot запускает его с фиксированными аргументами:
`--process_name <exe> --output_file <abs.csv> --timed <s> --terminate_after_timed --terminate_on_proc_exit --stop_existing_session --session_name FramePilotCapture --no_console_stats`.
Досрочная остановка: `--terminate_existing_session --session_name FramePilotCapture` (горячая клавиша Ctrl+Shift+F10).

Колонка времени кадра выбирается по приоритету: `MsBetweenPresents` → `MsBetweenAppStart` → `FrameTime`; использованная колонка сохраняется в сессии и в отчёте. Если в CSV несколько swap chain, анализируется та, у которой больше кадров (с предупреждением). Обрезанные строки пропускаются и подсчитываются.

## Определения (покрыты тестами `MetricTests`)
- Средний FPS = 1000 · N / Σ frameTimeMs.
- Перцентиль — метод ближайшего ранга: `sorted[ceil(p/100·N) − 1]`.
- P99 = 99-й перцентиль времени кадра.
- **1% low FPS = 1000 / mean(k самых медленных кадров), k = max(1, ceil(0.01·N)).** Это не 1000 / P99.
- Скачок = кадр > 2 × медианы времени кадра.
- Пороги: доля кадров > 8.33 / 16.67 / 33.33 / 50 мс.
- GPU busy ratio = медиана MsGPUBusy / frameTime (если метрика есть у ≥50% кадров).
- PC latency = медиана MsPCLatency, только если PresentMon её сообщил (≥50% кадров).
- «Ввод → кадр» = медиана MsClickToPhotonLatency — программная оценка PresentMon, **не** аппаратная click-to-photon задержка.
- Кадры с нечисловым или ≤0 временем отбрасываются.

## Что не является задержкой
Frame time и FPS не называются input lag. «Полная системная задержка» в v1 не показывается: для неё нужно аппаратное измерение (например, NVIDIA LDAT / Reflex Analyzer).

## Протокол сравнения
1. Зафиксировать версию игры, драйвер, разрешение, частоту монитора (сохраняются автоматически в `TestConditions`).
2. Прогрев 2–3 минуты на той же карте (шейдеры).
3. ≥3 прогона «До изменений» одинаковой длительности по одному сценарию (например, один маршрут в пустом лобби / Range).
4. Применить небольшой пакет изменений.
5. ≥3 прогона «После изменений».
6. Вердикт по метрике: «улучшение» только если **все** прогоны «после» лучше **всех** прогонов «до» (диапазоны не пересекаются). Иначе — «в пределах разброса».
7. Если условия различаются (версия игры, драйвер, разрешение, частота, длительность, смесь демо/реальных данных) — «условия различаются», вердикт не выносится.
8. При ухудшении — рекомендуется откат пакета и повторный прогон (обратный тест).

Матчи с разными игроками, картами и ситуациями не являются лабораторным A/B-тестом; интерфейс просит одинаковый сценарий.

## Ограничения
- PresentMon документирует ограничения части GPU-метрик при аппаратном планировании GPU (HAGS); это указано в ограничениях правил.
- ETW требует прав администратора или членства в «Performance Log Users».
