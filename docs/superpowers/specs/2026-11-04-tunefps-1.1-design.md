# TuneFPS 1.1 — «Видно, почему лагает»: спецификация

Дата: 2026-11-04. Статус: на проверке у владельца.
Основа: `main` @ 3150149 (приложение 1.0.1, сайт TuneFPS). Макет и motion-видео согласованы в чате 2026-11-04.

## 1. Цель и критерии успеха

Игрок записывает сессию CS2 или VALORANT и видит не только «были скачки», но и **что совпало с каждым скачком** (видеопамять, подкачка, троттлинг CPU, фоновый процесс, лимит GPU), **во что упирается игра** (CPU или GPU) и **какая задержка**. Интерфейс программы переведён на бренд TuneFPS с согласованным языком движения.

Успех:
- в демо и на реальной записи у каждого скачка есть атрибуция или честное «совпадений не найдено»;
- ни одна новая функция не пишет в систему, не внедряется в игру и не закрывает программы;
- обновление 1.0.1 → 1.1 сохраняет журнал изменений и откат (те же пути, AppId, ID действий);
- CI: сборка .NET 10, все старые и новые тесты зелёные; интерфейс проверен по чек-листу в `--design-preview`.

Вне релиза 1.1: исправления в один клик (частота монитора, режим питания), сеть — релиз 1.2; тренды и регрессии — 1.3.

## 2. Неизменяемые ограничения

- Запреты из `docs/RULES_POLICY.md` и `THREAT_MODEL.md` действуют полностью: не отключаем Defender, брандмауэр, обновления, Secure Boot, TPM, целостность памяти; не трогаем античиты; без внедрения, чтения памяти игр, драйверов ядра, правок BCD/HPET, массового отключения служб, «очистки RAM», разгона, BIOS; не закрываем программы пользователя.
- Приложение остаётся asInvoker. Новые датчики — только пользовательские API (PDH, DXGI, NVML), только чтение.
- Совместимость: `%LOCALAPPDATA%\FramePilot\framepilot.db`, `sessions\*.csv`, AppId установщика, имя exe, префикс лицензий `FP1.`, ID действий, ключи целей в журнале, схема отчёта `framepilot.report/1` — без изменений. Новые поля только добавляются.
- Данные остаются на компьютере. Имена фоновых процессов хранятся локально и в экспорт отчёта попадают только по явному флажку.

## 3. Новые возможности

### 3.1 Датчики во время записи (новый проект `FramePilot.Sensors`)

`SensorSampler` запускается вместе с PresentMon и снимает выборку каждые 100 мс (10 Гц) до конца записи. Каждый датчик — `Measured<T>`: если источник недоступен, причина пишется в отчёт, числа не выдумываются.

| Датчик | Источник | Счётчик / вызов |
|---|---|---|
| Частота CPU, % от номинала | PDH | `\Processor Information(_Total)\% Processor Performance` |
| Ограничение CPU | PDH | `\Processor Information(_Total)\% Performance Limit` (<100 = лимит по питанию/температуре) |
| Загрузка CPU игрой и вне игры | PDH | `\Process(*)\% Processor Time` → игра / сумма остальных / топ-3 процесса |
| Загрузка GPU игрой | PDH | `\GPU Engine(pid_<игра>*engtype_3D)\Utilization Percentage` (сумма) |
| Видеопамять игры и бюджет | PDH + DXGI | `\GPU Process Memory(pid_<игра>*)\Dedicated Usage`, `\GPU Adapter Memory(*)\Dedicated Usage`; объём — `IDXGIAdapter3`/`DXGI_ADAPTER_DESC.DedicatedVideoMemory` |
| Подкачка | PDH | `\Memory\Page Reads/sec`, `\Memory\Pages Input/sec` |
| Температура, мощность и причины снижения частот GPU | NVML (`nvml.dll` из драйвера NVIDIA) | `nvmlDeviceGetTemperature`, `nvmlDeviceGetPowerUsage`, `nvmlDeviceGetCurrentClocksEventReasons` (fallback `…ThrottleReasons`) |

NVML загружается динамически; если его нет (AMD, Intel, нет драйвера) — датчики GPU-температуры «недоступны: NVML не найден». Счётчики PDH ищутся по имени; если экземпляр не найден (другая локаль/старая Windows) — тоже `Unavailable` с причиной.

Хранение: `sessions\<id>.sensors.csv` рядом с CSV кадров (время от старта PresentMon, по колонке на датчик). Время датчиков сводится к шкале PresentMon по общей отметке старта (QPC); ожидаемая погрешность до ±50 мс, в интерфейсе подпись «±0,1 с».

### 3.2 Атрибуция скачков (`FramePilot.Diagnostics.SpikeAttributor`)

Скачок — кадр длиннее 2 × медианы (определение не меняется). Для каждого скачка берётся окно датчиков [t − 500 мс; t + 100 мс] и сравнивается с базой сессии (медиана и MAD каждого датчика). Кандидаты, в порядке приоритета:

1. **Видеопамять заполнена** — видеопамять игры ≥ 95 % бюджета, или выделенная память адаптера ≥ 97 %, вместе с ростом подкачки.
2. **Подкачка с диска** — Page Reads/sec выше 95-го перцентиля сессии и > 50 стр/с.
3. **Троттлинг CPU** — `% Performance Limit` < 90 или частота < 85 % медианы сессии.
4. **Лимит GPU** — NVML сообщает причину снижения частот (питание, температура, аппаратное замедление).
5. **Фоновый процесс** — CPU вне игры выше базы на 15 п. п.; называется самый нагруженный процесс.
6. **Сторона кадра** (если других совпадений нет) — по самому кадру PresentMon: `CPUBusy` ≫ `GPUBusy` → «задержка на стороне CPU/движка», наоборот → «на стороне GPU».
7. Иначе — **«Совпадений не найдено»** (например, компиляция шейдеров или сеть: мы их не видим и не угадываем).

Формулировка всегда «совпало с», не «вызвано». Сводка сессии: «у 3 из 3 скачков есть совпадение», плюс группировка по причинам. Вычисление — чистая функция от кадров и датчиков, покрыта тестами на синтетических рядах (каждый пункт, пограничные значения, отсутствие датчиков).

### 3.3 Узкое место и задержка (`FramePilot.Diagnostics.BottleneckClassifier`)

По кадрам с данными PresentMon 2: кадр «упирается в GPU», если `GPUBusy / FrameTime ≥ 0,85`, иначе «в CPU/движок». Результат — доли кадров (например, «GPU 72 %, CPU 28 %») и медианы `CPUBusy`, `GPUBusy`. Если колонок нет (старый PresentMon) — блок «недоступно: нужен PresentMon 2.x».

Задержка: при Reflex — медиана `PCLatency` («задержка ПК») и, если есть, `ClickToPhotonLatency`; без Reflex — медиана `DisplayLatency` (новое необязательное поле `FrameSample.DisplayLatencyMs`, колонки `DisplayLatency`/`MsDisplayLatency`) с подписью «задержка вывода кадра, без учёта ввода». Существующие правила `GpuLimitedRule` и `CpuOrEngineLimitedRule` переходят на классификатор, их ID и тексты рекомендаций не меняются.

### 3.4 Метка лага

Новая глобальная горячая клавиша **Ctrl+Shift+F9** во время записи ставит метку «тут лагнуло» (Ctrl+Shift+F10 по-прежнему останавливает запись). Подтверждение — короткий системный звук (отключаемый в Настройках); оверлея нет. Метки сохраняются в сессии (`Markers: [{ TimeMs }]`), на ленте — флажок; к каждой метке подбирается ближайший скачок в окне ±1 с и его атрибуция. Если клавиша занята другой программой — сообщение в Настройках, функция выключена.

### 3.5 Автозапись

Настройка «Записывать автоматически» (по умолчанию выключена). `GameWatcher` раз в 2 с проверяет процессы `cs2.exe` и `VALORANT-Win64-Shipping.exe`. После запуска игры ждёт настраиваемую паузу (по умолчанию 120 с, чтобы пройти меню и загрузку) и записывает 60 с с меткой «Авто», не чаще одного раза за запуск игры.

Ограничение: PresentMon сейчас запускается с повышением прав (окно UAC). Посреди игры это недопустимо, поэтому автозапись доступна только если запись работает **без UAC** — пользователь входит в группу «Пользователи журналов производительности». Программа это проверяет и, если нет, показывает инструкцию (сама группу не меняет: это изменение безопасности, его делает пользователь).

## 4. Интерфейс (WPF)

Навигация (6 разделов): **Обзор**, **Замер** (запись + список сессий), **План** (рекомендации + применение), **Изменения** (история + восстановление), **Компьютер** (железо + игры), **Настройки**. Существующие ViewModel переиспользуются; объединяются только представления.

- **Обзор** — по макету `tunefps-overview.png`: 4 KPI (средний FPS, P99, 1% low, скачки), лента времени кадра с ромбами скачков, флажками меток и подсказкой причины; чипы причин; распределение, «до/после», «Что найдено» с одной синей кнопкой. Новый блок «Узкое место и задержка».
- **Замер** — живая лента и строки датчиков; красный луч скачка, подсветка совпавшего датчика; кнопки «Остановить» и подсказка про Ctrl+Shift+F9.
- **План, Изменения, Компьютер, Настройки** — новая визуальная система; логика без изменений (в 1.1 «План» показывает существующие 3 действия; макетные исправления монитора и питания появятся в 1.2).
- `--design-preview`: отдельная БД, демо-данные с атрибуциями и метками, запись/применение заблокированы на уровне сервиса, плашка «ДЕМО» в заголовке.

Визуальная система: токены из `docs/brand/tunefps/design-system` (`TuneFPS.Theme.xaml`), шрифты Archivo Black / Inter Tight ExtraBold (кириллица) / Inter встраиваются ресурсами, тёмная тема, контраст по `contrast-report.md`, фокус 2 px `#4C9DFF`, DPI 100–200 %, режим высокой контрастности.

### 4.1 Язык движения

| Свойство | Значение |
|---|---|
| Появление | `cubic-bezier(.16,1,.3,1)` — WPF `KeySpline 0.16,1 0.3,1` |
| Перемещение | `cubic-bezier(.65,0,.35,1)` |
| Уход | `cubic-bezier(.7,0,.84,0)`, 120 мс |
| Базовая единица | 250 мс; микро 120 мс; герой 1,1 с |
| Шаг между элементами | 40 мс, общий ≤ 700 мс |
| Отскок | только хитмаркер скачка (`.34,1.56,.64,1`, 280 мс) |

Сцены: **Обзор** — один раз при новой сессии: сканер ленты 1,1 с, хитмаркеры, досчёт KPI 0,9 с, рост гистограммы, сдвиг «после». **Замер** — живая лента (обновление по кадру отрисовки), луч скачка 180 мс + подсветка датчика. **План** — нажатие 0,97, строки «крутится → галочка», прокрутка значения, уведомление снизу справа.

Доступность: если `SystemParameters.ClientAreaAnimation == false` или включена высокая контрастность — уровень 1 (сканер, кольца, лучи, прокрутка цифр) убирается, уровень 2 становится сменой прозрачности ≤ 150 мс, уровень 3 (фокус, индикатор записи без пульсации) остаётся. Анимируются только трансформации и прозрачность; живая лента рисуется через `DrawingVisual` с ограничением 60 кадров/с и паузой, когда окно свёрнуто.

### 4.2 График времени кадра

Новый `FrameTimeChart` (замена текущего): `DrawingVisual`, прореживание min/max с сохранением скачков, максимум не обрезается; ромбы скачков, флажки меток, линия P99, линия бюджета частоты монитора. Клавиатура: ←/→ — по кадрам, Tab/Shift+Tab — по скачкам, Enter — подсказка. `AutomationPeer` с текстом «Скачок 12,4 с, 18,6 мс, совпало: видеопамять заполнена».

## 5. Данные и совместимость

- `SessionRecord` получает необязательные поля: `SensorsCsvPath`, `Markers`, `SpikeAttributions`, `Bottleneck`, `Latency`. Старые сессии читаются (поля null → блоки «нет данных датчиков»).
- Схема БД остаётся версии 1 (данные — в JSON сессии и CSV-файлах); миграция не нужна.
- Отчёт `framepilot.report/1` получает необязательные `spikeAttributions`, `markers`, `bottleneck`, `latency`; веб-просмотрщик показывает их, если они есть, и молчит, если нет.
- Версия приложения 1.1.0; установщик — тот же AppId, обновление поверх.

## 6. Тесты и проверка

- Юнит-тесты: `SpikeAttributor` (по одному тесту на каждую причину, пороги, отсутствие датчиков, «не найдено»), `BottleneckClassifier`, разбор новых колонок PresentMon, CSV датчиков (запись/чтение), выравнивание меток, автомат `GameWatcher` (фейковый источник процессов), чтение старых сессий без новых полей, отчёт с новыми полями и без.
- Существующие 87 тестов, включая запреты (`NoAutoApplicableRule_TouchesSecurityFeatures`, `ValorantSecurityRequirementsRule`, `RegistryAllowlist`), проходят без изменений.
- CI (`build.yml`, windows-latest): сборка, тесты, публикация, установщик. Релиз — только по команде владельца.
- Ручной чек-лист на ПК владельца: `--design-preview` на 100/150/200 % и с выключенной анимацией Windows; реальная запись CS2 30–60 с с одной меткой Ctrl+Shift+F9; обновление поверх 1.0.1 с активным изменением и откат после обновления.

## 7. Порядок работ

1. Тема, шрифты, оболочка и навигация WPF; `--design-preview` на демо-данных.
2. `FrameTimeChart` и экран «Обзор» с языком движения.
3. `FramePilot.Sensors` + CSV датчиков + интеграция в `CaptureService`.
4. `SpikeAttributor`, `BottleneckClassifier`, задержка; экран «Замер».
5. Метка лага, автозапись, Настройки.
6. Остальные экраны в новой системе; отчёт и веб-просмотрщик.
7. CI, чек-лист, сборка установщика (без публикации релиза).
